## Microsoft Learn Insights

- Microsoft Foundry is a unified Azure platform for enterprise AI operations that combines models, agents, tools, monitoring, and evaluations under one management model.
- For security architecture, it uses a top-level Foundry resource for governance and separate projects for development isolation and access boundaries.
- Azure RBAC can be scoped at both the resource and project level; least-privilege patterns include assigning Azure AI User roles and using managed identities for automation.
- Connected services like Storage, Key Vault, and Azure AI Search remain separate Azure resources with their own networking, access, and compliance controls.
- Security and observability are built in through Azure Monitor, diagnostic logs, and security alerting; Foundry Control Plane adds centralized compliance and threat visibility across projects.

Security and governance considerations:
- Plan explicit boundary separation between Foundry governance, project workloads, and connected Azure resources.
- Use private networking, customer-managed encryption, RBAC scoping, and managed identities where required.
- Treat Defender for Cloud, Microsoft Purview, and Azure Policy as key governance controls for compliance and threat protection.
- Verify whether a capability is available at the project scope or only at the Foundry resource scope before designing access boundaries.

Practical next steps:
- Map your security requirements to Foundry resource vs. project scope before deployment.
- Define RBAC roles and managed identity assignments using least privilege.
- Enable diagnostic logging and review Azure Monitor metrics for resource and project activity.
- Evaluate Foundry Control Plane if you need cross-project compliance, fleet visibility, or integrated security signals.
